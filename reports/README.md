# reports/

Point-in-time records of completed work — investigation findings, fix summaries, verification snapshots, and decision write-ups produced during this project's development.

These files are useful as history: they explain what changed, why, and what was verified at the time. They are **not** authoritative about current state, and they are not kept up to date as the codebase evolves.

## For current state, read instead:

| What you want to know | Where to look |
|---|---|
| How the project works, how to run it, architecture decisions, gotchas | `replit.md` (repo root) |
| Database schema, migration workflow, production situation | `lib/db/README.md` |
| Security architecture, threat model, rate limiters, CORS/CSP | `threat_model.md` (repo root) |
