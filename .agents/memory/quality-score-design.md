---
name: Prospect quality score design
description: Design decisions behind the USMNT Tracker's prospect quality score (separate from eligibility confidence) — coefficient keying, formula shape, and seeding contract.
---

- Quality score answers "is he worth attention"; eligibility confidence answers "can he play for the US". Kept fully independent modules (`qualityScore.ts` vs `evaluateEligibility.ts`) — never share a number, never import from each other.
- League strength must key on API-Football's numeric `league.id`, never league name — the same league is spelled inconsistently elsewhere in this codebase (e.g. `clubs.league` holds both "MLS" and "Major League Soccer"). Verify ids live via `/leagues?search=`, never guess.
- `league_strength` seeding is insert-if-missing only (query existing ids, insert only the missing defaults) — never `onConflictDoUpdate`/upsert — so a hand-tuned coefficient always survives a restart. Verified via a live restart: second boot logged `inserted: 0, skipped: 21`.
- Formula: `quality = leagueStrength × ageMultiplier × performance` (raw range 0–2). Multiplicative on purpose so a strong league gates rather than just adds. **Never state a dry-run's findings without naming which database (dev vs. production) was actually queried** — an earlier report wrongly implied production when only dev (`heliumdb`) had been queried; the user caught this and it must not recur.
- Performance subtotal saturates minutes via `sqrt(minutes)/sqrt(3000)` (makes the 200→900 min gap matter far more than 2400→3100) and drops rating from the weighted mix entirely (not zeroing it) below a ~300-minute floor, redistributing its weight to minutes/starts. Unchanged since first version — do not touch without an explicit request.
- Age multiplier table now collapses hard past prospect age rather than tapering: 16→2.0 … 22→1.0, then 23→0.85, 24→0.4, 25→0.2, ≥26→0.1 (was a flat 0.9 floor from 23 up — that let high-minute 29-31-year-olds still rank respectably, which defeated the point of a *prospect* queue). Neutral 1.0 when age is unknown.
- Raw→0-100 normalization divides by a realistic ceiling (0.7), not the theoretical max (2.0) — real raw scores rarely exceed ~0.6-0.9, so dividing by 2.0 compressed the whole pool into the bottom third of the scale (adjacent ranks a point or two apart). This is a monotonic (rank-preserving) transform, factored into its own pure function (`normalizeRawScore`) specifically so it can be unit-tested for that property independent of the rest of the formula.
- `selectPrimaryLeagueBlock` excludes domestic/continental cups (`isCupCompetition`: "Cup", "Pokal", "Coppa", "Copa del Rey", "Trophy", "Shield", "Supercup", UEFA Champions/Europa/Conference League, Libertadores/Sudamericana) in addition to friendlies and NT comps — a cup run must never outrank/replace the real league as "primary", and a cup-only candidate falls back to the unknown-league coefficient with a warning rather than picking the cup.
- The displayed "club" for a scored candidate must come from the *selected primary league's team* (`QualityScoreInputs.leagueTeamName`), not `player_candidates.club_id` — that column holds whatever roster discovery found the player on, which can be a youth-national-team roster (e.g. "United States U20") used purely as a discovery source, not the player's real club. `/admin/review-queue` prefers `qualityScoreInputs.leagueTeamName` and falls back to the `clubsTable` join only pre-scoring.
- Quality scoring must be wrapped in try/catch at every call site inside `playerDiscovery.ts` (discovery insert, onConflictDoUpdate, rescoreAllCandidates) — a scoring failure (e.g. DB blip loading `league_strength`) must leave the candidate merely unscored (`qualityScore: null`), never abort eligibility discovery/rescoring, which runs in the same pass.
- A correct dry run must replicate `/admin/review-queue`'s live-age filter (`ageFromBirthDate(dob) ?? age <= maxAge`) before ranking — querying `pending`/`needsReview` rows directly over-counts (in one dev-DB run: 111 raw rows vs. 73 after the same filter the admin UI applies), since the UI already hides over-age rows that just haven't been rescored/dismissed yet.
- `rescoreAllCandidates`'s candidate-selection query (`status='pending' OR eligibilityConfidence IS NULL`) does not check `needsReview` — a hypothetical candidate with `needsReview=true` but a non-pending status and a non-null confidence would show in the review queue (which does check `needsReview`) but never pass through the age-dismissal path. Latent gap, not yet triggered by any observed row as of 2026-08-26.
- Old unclassified/high-minutes leagues (NWSL Women, Leagues Cup, MLS Next Pro, regional lower-division names like "Primera División - Clausura") still surface after cup-exclusion — expected, since those aren't cups, just genuinely unclassified leagues; keep adding real coefficients for them in `leagueStrengthDefaults.ts` as they appear rather than special-casing in the scorer.
- Admin (`/admin/*`) endpoints are entirely absent from `lib/api-spec/openapi.yaml`/codegen — that pipeline only covers the public API. Don't add a single admin endpoint to the spec without also deciding the broader convention; flagged as a follow-up rather than done ad hoc.
