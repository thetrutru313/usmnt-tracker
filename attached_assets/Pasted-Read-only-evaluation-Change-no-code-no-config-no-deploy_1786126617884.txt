Read-only evaluation. Change no code, no config, no deployment settings.

The goal is to fix unreliable background-job execution. The original plan was to
split the API server into separate web and worker processes. Before building
that, establish whether it is necessary — or even possible on this platform.

WHAT WE KNOW

  - .replit sets deploymentTarget = "autoscale", which sleeps the process when
    traffic is quiet.
  - All background jobs are setInterval timers started from index.ts.
  - Live sync_metadata shows the DAILY syncs are running roughly on time
    (~26 h intervals). The HOURLY ones miss cycles — fixtures last ran ~2 h
    before a check with a 50-minute cooldown.
  - The timestamps cluster: the three daily syncs share an identical second,
    the two hourly ones share another. That is the signature of jobs firing in
    a burst at process start, not independent timers.
  - lib/apiFootballSync.ts throttles outbound calls with an in-memory variable,
    so two concurrent instances each assume the full rate-limit budget.
  - runCriticalStartupSeeds() runs BEFORE app.listen(), so the port is closed
    during that window. Deployment logs show 9 healthcheck failures over ~2
    seconds at startup.

cannot be deployed here at all, and I need to know that before we build it.
