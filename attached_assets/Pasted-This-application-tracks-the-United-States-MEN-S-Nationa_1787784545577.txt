This application tracks the United States MEN'S National Team. Women's
players, women's clubs, and women's competitions are out of scope
everywhere in this codebase. This has leaked into the candidate pool
repeatedly and needs a structural fix, not a one-off cleanup.

## 1. Find the entry point

Read-only first. Report before changing anything:

- Which candidates in the pool are female, and how did they get there?
  Check for NWSL, women's UEFA competitions, SheBelieves Cup, and any
  team or league with "Women"/"Feminine"/"Femenil" in the name.
- Does API-Football expose gender on /teams, /leagues, or /players
  responses? Name the exact field.
- Which code path admitted them — the squad scan in discoverUSProspects,
  the clubs table, or somewhere else?

## 2. Filter at ingest

Once you have the entry point, block it there. A female player must not be
able to enter player_candidates at all. Prefer API-Football's own gender
field over name matching; use name patterns only as a secondary backstop.

Apply the same exclusion to any club or league sync that could introduce
women's teams into the clubs table.

## 3. Regression test

Add a test that fails if a women's league, women's club, or female player
can reach the candidate pipeline. Make its failure message state plainly
that this is a men's-only tracker. This test is the point of the whole
task — it must be impossible to reintroduce this without the suite going
red.

## 4. Document the constraint

Add a section near the top of replit.md, under a heading like "Scope —
read this first":

  This application tracks the United States MEN'S National Team only.
  Women's players, clubs, and competitions are out of scope in every part
  of this codebase — discovery, candidates, fixtures, rankings, and
  scoring. Never add, sync, or surface women's data. A regression test
  enforces this; if it fails, the fix is to exclude the data, never to
  weaken the test.

## 5. Clean up existing rows

Give me SQL to remove or dismiss the female candidates currently in the
pool, to run by hand. Do not run it yourself, and do not put it in a
migration — Publish carries DDL only.

Run pnpm run typecheck, pnpm run lint, and the full suite.
