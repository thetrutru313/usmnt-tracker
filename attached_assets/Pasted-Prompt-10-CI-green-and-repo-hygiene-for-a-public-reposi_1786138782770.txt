Task A — make CI green (the important one)

Do NOT add API_FOOTBALL_KEY to GitHub Actions secrets. Do NOT write ${{ secrets.API_FOOTBALL_KEY }} anywhere. Read the diagnosis first.

The nine failures all log Error: API_FOOTBALL_KEY is not set before asserting. That is real, but it does not mean CI needs the key.

artifacts/api-server/src/lib/apiFootballSync.ts:64-67:

js
export async function afFetch<T>(path: string, attempt = 0): Promise<T> {
  await throttle();
  const res = await fetch(`${BASE_URL}${path}`, {
    headers: { "x-apisports-key": apiKey() },   // <- throws here
  });

apiKey() (line 33) throws when the env var is unset. It sits in the argument expression to fetch, and JavaScript evaluates arguments before invoking the callee — so apiKey() throws before fetch is ever called.

All six failing files stub globalThis.fetch via vi.stubGlobal("fetch", ...). Those stubs are correct. They are simply unreachable, because the throw happens one expression earlier in the evaluation order. playerCentricSyncIntegration.test.ts even says "(no real API)" in its own test name. These tests were never meant to need a key.

The fix — one line. In the workflow's job-level env: block, beside the placeholder that already exists for exactly this reason:

yaml
    env:
      DATABASE_URL: postgres://postgres:postgres@localhost:5432/usmnt_test
      ADMIN_PASSWORD: ci-placeholder-admin-password
      API_FOOTBALL_KEY: ci-placeholder-api-football-key   # <- add this
      PORT: "5173"
      BASE_PATH: /

The value is never transmitted. It is interpolated into a header object that is handed to a stubbed fetch, which discards it.

Why a real key would be worse than useless. Today, a test that reaches this code path unmocked fails loudly. With a real key present, that same test would quietly hit the live paid API and pass — the failure you cannot see. It would also burn paid quota on every push and place a paid credential in a public repository's Actions environment for zero benefit.

Already checked, do not redo: five other test files reference the sync functions without stubbing fetch (fixtureSyncVisibility, internationalWindowGuard, livePollPostMatchTrigger, postMatchStatsTrigger, repairPassReserveGuard). All five passed in CI, which proves they never reach afFetch. Four only name the functions in comments; postMatchStatsTrigger injects syncFn. A placeholder key changes exactly one thing: it makes six files' existing mocks reachable.
