TASK C — Rankings must rank on the whole current season
═══════════════════════════════════════════════════════════════════

STATED PRODUCT INTENT: the Rankings page is focused on the CURRENT SEASON. The
player profile shows the current season PLUS PAST SEASONS, with a dropdown.

The profile already does this correctly. Rankings does not, in two ways.

--- C1: Rankings ranks on current-club minutes, not season minutes ---

rankings.ts:87-94 (mostMinutes) and :95-105 (mostGoalContributions) read
periodType = 'season'. playerStatsSync.ts:861-867 builds that row with a
CURRENT-CLUB-ONLY filter; season_all (:868-876) is the all-clubs variant.

Production evidence (Q8). Every row below is the SAME SEASON, 2025 — this is
not a current-vs-past-season difference:

  Player               Rankings ranks them on   Actual 2025 season total
  Zavier Gozo          0 goals / 90 min         4 goals / 2108 min
  Benjamin Cremaschi   0 goals / 230 min        1 goal  / 2046 min
  Yunus Musah          0 goals / 119 min        2 goals / 951 min
  Damion Downs         0 goals / 395 min        0 goals / 945 min

A "Most Minutes" leaderboard ranking Gozo on 90 of the 2,108 minutes he played
this season is not a labelling problem. Every mid-season transferee is buried.

--- C2: Rankings applies no season-year filter at all ---

rankings.ts:92 and :104 filter ONLY on periodType. Each player's `season` row
is whatever year last returned current-club data (playerStatsSync.ts:895-901),
and that is not the same year for every player — Q8 shows Matai Akinmboni's
row is 2024 while the others are 2025.

So the leaderboard currently compares one player's 2025 totals against another
player's 2024 totals inside a single ranked list.

--- THE FIX ---

Change mostMinutes and mostGoalContributions to read ALL-CLUBS TOTALS FOR ONE
EXPLICIT SEASON YEAR:

  1. Determine the current season year server-side. DERIVE IT — DO NOT
     HARDCODE 2025. seasonYearCandidates() in playerStatsSync.ts already
     encodes this project's rule for which season labels are plausible. Reuse
     it; export it if it is not already exported. Do not invent a second rule.
  2. Query periodType = 'season_all' with an explicit
     season = <current season year> filter.
  3. Players with no season_all row for that year drop off the leaderboard.
     That is correct — they have no current-season data.

DO NOT CHANGE ANY OF THE FOLLOWING:
  - computeFormBadge (queries.ts:75-97) and computeFormTier
    (playerStatsSync.ts:381-408), which use periodType = 'season' as their
    baseline. Current-club-only is CORRECT there, for the reason documented at
    playerStatsSync.ts:861-863 — mixing prior-club data would skew the form
    delta for a player who just transferred. Both period types must keep
    existing; this task changes only which one Rankings reads.
  - bestWeekendPerformances (rankings.ts:78-86), which reads match_logs on a
    7-day window and is unaffected.
  - Anything on the player profile. It is already correct.

LABELLING, AFTER THE QUERIES ARE FIXED: add a short qualifier naming the
season year each leaderboard covers (e.g. "Most Minutes — 2025").
