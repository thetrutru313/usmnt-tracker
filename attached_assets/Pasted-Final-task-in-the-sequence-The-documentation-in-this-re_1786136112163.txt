DECISION TO REFLECT: 7C IS NOT PROCEEDING.

We evaluated switching deploymentTarget from "autoscale" to "vm" (Reserved VM)
and decided against it for now. Document the CURRENT state — autoscale — and
the reasoning, so nobody re-litigates it from scratch:

  - The correct value would be "vm", not "reserved_vm". Worth recording; the
    first guess was wrong.
  - Cost is roughly $15.18/month flat versus usage-based autoscale.
  - What it would buy: syncs on real schedules rather than at process wake-ups,
    a single-process API-Football rate-limit budget, and reliable live-score
    polling during matches.
  - Why we declined: every sync runs immediately on cold start, gated by
    syncGuard's cooldown, so opening the app refreshes stale data — the refresh
    lands a view later, which is fine for schedule and streaming information.
    Live scoring is a secondary feature here, not the app's purpose.
  - And the migration plan targets a host with persistent processes anyway, so
    paying for always-on twice makes no sense.

Do NOT change deploymentTarget. Do NOT treat this as unfinished work.

The current security architecture, which the rewrite must describe accurately:

  - Admin auth is server-side sessions. ADMIN_PASSWORD is the LOGIN credential
    only, checked once at POST /admin/transparency/verify. Success issues a
    UUID token; only its SHA-256 hash is stored, in admin_sessions. Sessions
    expire and can be revoked. requireAdminSession gates every admin surface.
  - Rate limiters: global 300/min, search 60/min, anonymous-user provisioning
    5/15min, admin verify 5/15min.
  - CORS: allowlist from ALLOWED_ORIGINS plus Replit's domain variables.
    http://localhost:* is additionally permitted when NODE_ENV is not
    production, so dev exercises CORS rather than bypassing it.
  - CSP: connect-src is 'self' plus one scoped exception — the object-storage
    bucket path, because invoice uploads PUT directly from the browser.
    Document that this exception disappears if uploads are ever proxied
    through the API server.
  - Invoice downloads validate the requested path against
    transparency_months.invoice_urls before signing. Before that check existed,
    an unauthenticated request could obtain a signed URL for any object in the
    private bucket — record that, it is the sort of thing worth remembering.
  - Anonymous user tokens and recovery tokens are stored hashed, never in
    plaintext.

Keep the existing structure — Assets, Trust Boundaries, Scan Anchors, Threat
Categories. Add a "Last verified" date so the next reader knows how much to
trust it.
