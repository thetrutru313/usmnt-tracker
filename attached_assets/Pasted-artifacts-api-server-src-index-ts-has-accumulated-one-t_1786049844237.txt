STEP 3 — Classify, then act only on the safe ones.
────────────────────────------------------------------------------------

  DELETE — taken effect in BOTH databases AND the condition cannot recur
    because a real guard exists in the sync path. Remove the block.

  KEEP — the condition can still recur and the block is the only thing
    preventing it. Leave it, but add a comment naming what would have to be
    fixed for it to become removable. Report these to me.

  FIX THE CAUSE — the condition can recur and the proper fix belongs in the
    sync code rather than at startup. Describe the fix. DO NOT implement it in
    this task; that is a separate change with its own testing.

  BLOCKED — has NOT taken effect in one or both databases. Report it and STOP
    on that block. Do not delete it. Note that with production read-only via
    the executeSql proxy, there may be no way to apply the repair other than
    leaving the startup block in place until the deploy-step path exists.
