# Admin Login Diagnostic Report
**Date:** 2026-08-06  
**Environment:** Production  
**Status:** Root cause identified — two issues confirmed

---

## Summary

Admin login is broken in production after the session-token migration. Verify (`POST /admin/transparency/verify`) works correctly and returns 200, but every subsequent admin request returns 401. The cause is a pair of defects that compound each other: a confirmed code bug in `ReAuthModal.onSuccess` (token is never propagated to React state) and a timing race between the `validate` effect and `LoginForm` submit. Together they create a login loop that exhausted the rate limiter within 35 seconds of the first attempt.

## Root Cause — Two Issues

### Issue A (confirmed code bug): `ReAuthModal.onSuccess` discards the new token

`ReAuthModal` declares its callback as `onSuccess: () => void`. The handler correctly writes the new UUID to localStorage (`saveSession(res.token, ...)`), but then calls `onSuccess()` with no argument.

The wiring in `AdminPanel` (lines 906–912):

```tsx
<ReAuthModal
  onSuccess={() => {
    setShowReAuth(false);       // closes modal
    setBannerDismissed(false);  // cosmetic only — no setToken call
  }}
  onCancel={() => setShowReAuth(false)}
/>
```

**Consequence after a successful re-auth:**

| State | Value |
|---|---|
| `localStorage` | new UUID ✅ |
| Root `Admin.token` | **old value** ❌ never updated |
| `AdminPanel.token` prop | **old value** ❌ |
| All subsequent `apiFetch` calls | `Authorization: Bearer <oldToken>` |

`requireAdminSession` hashes the old token → finds no matching row → **401**.  
The 401 from the `validate` effect → `handleUnauthorized()` → `clearSession()` wipes the newly stored UUID → `setToken(null)` → LoginForm shows again → loop.

The same bug exists in `AdminReviewQueue.tsx` — same `ReAuthModal` usage, same `onSuccess: () => void` wiring.

**The fix (not yet applied — awaiting sign-off):**

Change `ReAuthModal` prop type to `onSuccess: (token: string) => void`, call `onSuccess(res.token)` in `handleSubmit`, and update both `AdminPanel` and the equivalent component in `AdminReviewQueue` to call `setToken(newToken)` (or pass a new `onReauth` prop down from the root).

---

### Issue B (timing race): stale `validate` callback races with a fresh verify

The `validate` effect and `LoginForm.handleSubmit` execute concurrently — `validate` is a `useEffect` that fires immediately on mount; the user's submit is a parallel async task.

**Race sequence:**

```
t = 0 ms    AdminPanel mounts (old token from localStorage)
t = 0 ms    validate fires → GET /admin/session with oldToken  [in-flight]
t = 0 ms    data queries fire → GET /admin/* with oldToken      [in-flight]
t = ~10 ms  User clicks submit → verify fires                   [in-flight]

t = 187 ms  data queries return 401 → React Query catches, no logout
t = 246 ms  verify returns 200 → saveSession(newToken) → setToken(newToken)  [state A]
t = 250 ms  validate returns 401 → clearSession() ← wipes newToken from localStorage!
                                 → setToken(null)                             [state B]
```

React batches state A (`newToken`) then state B (`null`) — final state is `null`. LoginForm shows. The freshly issued token is gone from localStorage (though the DB row is still valid and un-revoked).

The user re-enters the password → verify → 200 → same race → same result. The 3-second interval between batches matches the round-trip time of validate (old token cache is warm after the first miss, so subsequent validates complete in ~33 ms, but the user still has to see LoginForm, re-type, and re-submit).

After **four** successful 200 responses, the **fifth** attempt at 22:19:50 hits the rate limiter (window: 5 per 15 minutes).

**The fix (not yet applied — awaiting sign-off):**

In the `validate` async function, before calling `handleUnauthorized`, confirm that the token currently in localStorage matches the one used for the failing request. If they differ, a new login has already succeeded; skip the logout.

```ts
async function validate() {
  try {
    await apiFetch("/admin/session", token);   // token captured at effect creation
  } catch (err) {
    if (err instanceof SessionExpiredError) {
      const stored = loadSession();
      // Only log out if no newer token has been written since this request started
      if (!stored || stored === token) {
        handleUnauthorized();
      }
    }
  }
}
```
